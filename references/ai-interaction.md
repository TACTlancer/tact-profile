# 用户面对 AI 时的样子（第十一维）

## 为什么单列一维

画像通常只回答「他是什么样的人」，但现代人有大量时间在和 AI 说话。

**对话记录是最干净的行为日志**——没有社交表演、没有熟人审查、没有场合压力。所以它能暴露一些在朋友圈里看不到的东西。

这一维回答的是：**他作为「工具使用者」是什么样。**

## 数据源

| 源 | 优点 | 注意 |
| --- | --- | --- |
| AI 对话导出（DeepSeek / Claude / ChatGPT） | 完整、可分主题 | 量最大，先脱敏 |
| 本机 agent 会话记录 | 含「纠错」这种高价值行为 | 路径含用户名 |
| 截图 | 任何平台都能补 | 需人工读 |

> 这类数据几乎一定含隐私。采集前先读 `privacy.md`。

## 十个观察维度

| # | 维度 | 看什么 | 低分 / 高分 |
| --- | --- | --- | --- |
| 1 | **工具观** | 当人 / 当工具 / 当伙伴 | 「AI 只是工具」↔「你也有感受吧」 |
| 2 | **期待角色** | 教练 / 镜子 / 执行者 | 「给我建议」↔「只评价，别建议」 |
| 3 | **纠错习惯** | 主动 / 被动 / 不纠 | 从不等问 ↔ 从不反驳 |
| 4 | **验证要求** | 要证据 / 要结论 / 要理由 | 「可信度如何」↔「直接给答案」 |
| 5 | **讨好容忍度** | 讨厌 / 无所谓 / 喜欢 | 「你的建议有点油腻」↔「谢谢」 |
| 6 | **指令风格** | 极简短句 / 长 prompt / 分步 | 「如何评价」↔ 三百字背景 |
| 7 | **事实与判断** | 会区分 / 混用 | 「不要揣测我的想法」↔ 默认合并 |
| 8 | **元要求** | 自审 / 反驳 / 不要求 | 「搞一轮自审再输出」↔ 不关心过程 |
| 9 | **关系定位** | 讨论对象 / 命令对象 | 「不是要求，是讨论」↔「照做」 |
| 10 | **分工偏好** | 明确分工 / 一锅炖 | 查资料归查资料、玩梗归玩梗 |

## 怎么采

```
1 导出对话（优先能导出的平台，实在不行截图）
2 统计：问题长度分布、重复句式 Top 5、纠错次数
3 摘 10 条代表性原话（一句一条）
4 按十维归档
```

**统计比印象可靠**：「如何评价」出现几十次，比「他好像很直接」有用。

## 怎么写

每条 = **特征 + 一句原话**。

写完再提炼两样：

### ① 一句话「理想协作者规格」

> 例：能反驳、能自审、不讨好、有证据、听得懂短指令，但不许当应声虫。

### ② 与其他维度是否同构

| 结果 | 说明 |
| --- | --- |
| **同构** | 一致性强——他怎么对人，就怎么对工具 |
| **不同构** | 有场景切换——对 AI 一套，对真人一套（同样有价值） |

## 纪律

1. **不评价 AI 的回答质量**——这一维只记用户侧行为。
2. **只摘「怎么说话」，不摘「说了什么」**——话题可能是隐私，句式不是。
3. **不推断「他在现实中也是这样」**——和 AI 说话的状态可能和现实完全不同。要看同构性，得另有证据。
4. 对话里的自述同样要过 `correction.md` 的语境判定——很多人对 AI 会玩梗、试探、夸大。

## 反模式

| 别做 | 为什么 |
| --- | --- |
| 用 AI 的回复反推用户 | 那是 AI 的话，不是他的 |
| 把「问得多」当成「兴趣大」 | 可能只是查资料 |
| 把「玩梗提问」当认真 | 见 `correction.md` 语境判定 |
| 统计 token/字数当「投入度」 | 字数 ≠ 重视 |
