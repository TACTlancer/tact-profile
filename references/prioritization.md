# 时效与重要性（判断的优先级）

## 为什么需要单列

画像里的判断**不是同等重要，也不是同时成立**：

- 有些是多年稳定的性格
- 有些是最近 1–2 年的变化
- 有些曾经成立、现在已不成立

混着写，读者会误判：把「最近才这样」当成「他本来就这样」，把「细节偏好」当成「核心人格」。

---

## 三档时效

| 档 | 判据 | 处理 |
| --- | --- | --- |
| **长期** | 3 年以上、多源印证 | 可以当性格用 |
| **变化中** | 近 1–2 年、有前后对比 | **不许当性格用**，必须标出来 |
| **已废** | 本人明确推翻 / 方案已换 | 标「已废」，但**保留记录** |

### 怎么判断「变化中」

找**前后对比**：

> 学生时「融入对方语境」→ 工作后「只留工作语境」→ 现在「为在乎的人创建语境」

三个时间点，两种模式，正在变——这就是「变化中」。

### 「变化中」的写法

不要写「他变得外向了」，要写：

> **社交是事件驱动，但恋爱能突破**（变化中：默认档 + 触发条件）

**保留原模式 + 标出触发条件**，比「他变了」准确。

---

## 三层重要性

| 层 | 判据 | 数量建议 |
| --- | --- | --- |
| **核心** | 能解释 50% 以上的行为 | **2–4 条** |
| **重要** | 管一个领域 | 5–8 条 |
| **参考** | 补充细节与边界 | 其余 |

### 核心怎么找

问一句：**删掉这条，画像还成不成立？**

不成立的是核心，成立的是参考。

---

## 「总开关」：把核心合成一条

核心几条往往指向同一个结构。

实测案例：

| 核心判断 | 它的反面 |
| --- | --- |
| 要确定性 | 不要概率和刺激 |
| 效率主义 | 不要重复劳动 |
| 性价比计算 | 不要浪费资源 |
| 怕失控的人 | 不要不可预测的人 |

→ 共同结构：**「降低不可控性」**

### 但总开关必须带边界

直接写「他所有选择都在降低不可控性」是**错的**——因为他在两个人的事上主动让渡控制权。

正确写法：

> **能由他决定的，他要确定；不能由他决定的，他接受不确定。**

**总开关 = 共同结构 + 反例边界。**

没有反例的「总开关」是过度概括，正是「过度压缩」要防的东西。

---

## 纪律

1. **每条判断标时效**——长期 / 变化中 / 已废，三选一。
2. **「变化中」不许当性格**，写「原模式 + 触发条件」。
3. **核心不超过 4 条**——超过说明还没找到结构。
4. **总开关必须有反例**，写在旁边。
5. **已废的判断不删**，标状态、留在变更记录里。

---

## 输出时的位置

| 文档层级 | 怎么放 |
| --- | --- |
| L1（一页版） | 只给「一句话 + 核心 2–3 条」，不列时效表 |
| L2 | 判断表加「时效」列 |
| L3 | 判断表加「时效」列 + 「怎么读」分层 + 总开关一节 |
