# 历史记录（史志维度）

## 为什么单列

画像回答「**他是谁**」，历史回答「**他做过什么**」。

两者互相支撑：

| 画像 | 历史 |
| --- | --- |
| 推断（A/B/C 级） | 事实（有记录） |
| 解释动机、偏好、三观 | 记录时间、地点、产出 |
| 容易漂移 | 可以对账 |

**历史是画像的锚**——画像说「他一直往下扎」，历史要能给出「2019 嵌入式 → 2026 敌人 AI」这条链。

---

## 两层结构

### 1. 时间线（年 / 月粒度）

一句话一件事，按时间排。不求全，求**可核对**。

```
2019-05  报名参赛，建立协作仓
2019-10  南京决赛 · 图书分拣 · 全国一等奖
2020-12  《初光》PVP 塔防（团队）
2021-06  入职
```

### 2. 事件卡（单个事件展开）

| 字段 | 内容 |
| --- | --- |
| **时间** | 精确到月（不确定就标「约」） |
| **地点** | 城市 / 场所 |
| **参与** | 独自 / 团队（几人）/ 和谁 |
| **做了什么** | 事实，**不带评价** |
| **结果** | 奖项 / 产出 / 失败 / 无疾而终（都算） |
| **证据** | 说说 / 相册 / 代码仓 / 官方新闻 / 本人回忆 |

---

## 多源交叉（核心方法）

| 源 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 自己的说说 | 当时的情绪、状态 | 事件的完整经过 |
| 相册 | 视觉证据、时间戳 | 为什么做 |
| 代码仓 / 作品 | 产出、协作关系、技术栈 | 动机 |
| 官方新闻 / 公告 | **第三方确认**（最硬） | 个人贡献比例 |
| 本人回忆 | 定性（做过/没做过） | **时间经常错** |

### 实测发现

本人回忆的**时间**不可靠，**事件**可靠。

| 事 | 本人回忆 | 实际 |
| --- | --- | --- |
| 图书分拣 | 「2020 上半年」「图书管理机器人」 | **2019-10**，官方叫「**图书分拣**」 |
| 微信小程序 | 「2020 上半年」 | **2019-05** |
| 《初光》塔防 | 「2020 上半年」 | **2020-12** |
| 炎魂冬令营 | 确定参加过 | 公开资料查不到，仓库可证时间 |

**所以：核实时间用记录，核实「有没有这回事」用本人。**

---

## 写作纪律

1. **历史只记事实，不记评价**——评价归画像。
2. **时间冲突时，有记录的为准**，本人回忆改标「约」。
3. **没有证据的事件**标「本人回忆，待核实」，不进正式时间线。
4. **不替事件补意义**——「那半年他在琢磨系统」这种话，除非本人说，否则不写。
5. **失败与无疾而终也要记**——只记成功会失真。

---

## 和画像的连接

写完历史，回头检查画像的每条判断能不能找到历史锚点：

| 画像判断 | 历史锚点 |
| --- | --- |
| 「一直往下扎」 | 2019 嵌入式 → 2026 敌人 AI |
| 「唯一完整游戏项目」 | 2020-12《初光》 |
| 「不展示成就」 | 一等奖在记录里，但不在对外文档里 |

**找不到锚点的判断，要么是错的，要么是还缺证据。**
