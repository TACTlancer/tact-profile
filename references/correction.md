# 纠偏协议（用户纠正事实错误时）

## 为什么单独立一节

**判断建立在事实上；事实错，判断就废。**

画像里最贵的错误不是「推断偏了」，是「事实错了还拿它推了一串结论」。所以纠偏不是打补丁，是**重算**。

---

## 三类纠正，处理不同

| 类型 | 例 | 处理 |
| --- | --- | --- |
| **事实错** | 「2022-2023 不是空档，在上班」 | 改事实 → **逐个检查依赖它的判断** |
| **语境错** | 「ADHD 是闹着玩的」 | 撤销或降级 → 移出结论，只留「他喜欢这种玩法」 |
| **推断错** | 「创作用意是混沌造成的」 | 撤销推断 → **保留事实描述**，不强行找解释 |

---

## 漂移检测（2026-11-21 新增）

同一份画像写多个版本时，判断会被反复转述，**每转一手就可能加一点自己的话**。

实测案例：

| 层 | 说法 | 偏移 |
| --- | --- | --- |
| 原话 | 「受不了太彰显自己的人，会默默远离」 | — |
| 版本 A | 「听不进话的，会默默远离」 | 「太彰显」→「听不进话」（换概念） |
| 版本 B | 「说了不算的，会远离」 | 再加「失信」这一层 |

三次转述，从「讨厌炫耀」漂成「讨厌失信」。

### 检查方法

对每条判断问一句：**这句能追到哪句原话？**

| 情况 | 判定 |
| --- | --- |
| 能追到原话 | 保留 |
| 追到的是上一版文档 | 继续往上追 |
| 追不到 | **漂移，删掉或降级为推断并标注** |

### 规则

1. **转述时不许加原话里没有的概念**。
2. 多版本共用一个「判断源」时，**以最早那版的原话为准**，不要以最近转述为准。
3. 改完一处漂移，**反查所有版本**（79/81/87/88 都要查）。

---

## 过度压缩（把分层压成一句）

**症状**：把多层结构压成一条漂亮的判断，读起来更有力，但丢了层次。

实测案例（2026-11-21，同一轮犯了三次）：

| 原本的结构 | 我压缩成 | 丢了什么 |
| --- | --- | --- |
| 游戏要能重来 / 现实认不可逆 / 两人不追求确定性 | 「把能重来当底线，对一切」 | 两个场域 |
| 多数事算性价比 / 少数事不算账、累了才停 | 「怕麻烦是性格」 | 「不算账」那半 |
| 游戏 + 生产实习 + 远程项目 | 「疫情半年在琢磨系统」 | 全部事实，还替人编了意义 |

### 为什么容易犯

- 一句漂亮的判断，看起来更像「结论」
- 分层写出来像「罗列」，不如金句有力
- 写的人自己会被自己的句子说服

### 怎么防

1. 写完一条判断，问：**它有几个场域 / 几种模式？**
2. 超过一个就**分开写**，不要合并
3. 判断的力度不来自绝对化，来自**准确**

### 规则

> **宁可写三条准确的分域判断，不写一条漂亮的万能判断。**

---

## 五步流程

```
1 记录原话（照抄，不改写）
2 定位依赖：这条事实出现在哪些结论里？
3 重算：受影响的判断逐条重判（保留 / 降级 / 撤销）
4 留痕：变更记录写「原判断 → 更正 + 依据」
5 反查：别处有没有用到同一个错误事实？
```

第 2 步最容易漏。一条事实往往被 3–5 处引用。

**例**：「2022-2023 职业空档」这一个错，污染了 02 时间轴、06 职业线、08 旅程图、10 缺口四处。

---

## 影响面登记表

纠偏时填这张表，防止漏改：

| 被纠事实 | 出现在哪 | 受影响判断 | 处理 |
| --- | --- | --- | --- |
| | 章节 / 行号 | | 保留 / 降级 / 撤销 |

---

## 纠偏后必做

- [ ] 受影响判断全部重判
- [ ] 置信度表更新（可能整条从「高」掉到「低」）
- [ ] 一页版（L1/总结）同步——只改长文不改摘要，等于没改
- [ ] 来源索引补上「本次纠偏来自本人」
- [ ] 反查同类错误

---

## 错误保留原则

**被推翻的判断不删。**

它们进「变更记录」，理由有三：

1. 错误本身是信息——它说明「这个人是怎么被误读的」；
2. 记录纠偏方式——先给事实、再给原因，这本身是画像；
3. 防止换个角度重犯。

---

## 主动请纠

每轮交付时主动问一句：

> 「哪条不对？直接说，我改。」

不要等用户自己发现。**用户纠一次的画面，胜过自己推十次。**

### 提问模板

| 场景 | 问法 |
| --- | --- |
| 刚写完一节 | 「这条判断的依据是 X，你觉得准吗？」 |
| 交付整篇 | 「哪条最不像你？」 |
| 有推断时 | 「这条是我推的（C 级），你认吗？」 |
| 版本更新后 | 「这版改了什么，有没有改错？」 |

---

## 事实与判断的分层写作

纠偏能生效的前提是**事实和判断分开写**：

```markdown
事实：2020-02~08 说说只有 25 条（B 级，数据）
判断：疫情居家、生活平淡（C 级，推断）
更正：本人确认「疫情在家，没啥事」→ 判断升级为 A 级
```

如果事实和判断混在一句话里，纠偏时就得整句重写，还容易连带删掉对的部分。

---

## 红线

- 不因为「用户纠正了」就否定全部结论——只改受影响的部分。
- 不把用户的纠正当「又一个数据点」塞进旧框架——该改框架就改。
- 不删错误记录。
- 不在纠偏后立刻求认可（「现在对了吧？」）——等下一轮验证。
